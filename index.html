Before you begin

  • Sign in to GitHub with the account whose username you submitted on the registration form.
  • Accept the invitation to your repository. GitHub emails it to you, and it also appears at github.com/notifications.
  • A GitHub 404 means your account does not have access yet, or the invitation is still pending.
  • The portal only constructs a link. GitHub permissions protect the private repository.

Seeing a 404?

GitHub shows the same 404 whether the repository is missing or you simply cannot see it, so work through these in order.

  • Wrong account. Check the avatar in the top-right corner on GitHub. If it is not the account you registered, sign out and sign back in with the right one.
  • Invitation not accepted. Open github.com/notifications or the invitation email, then accept.
  • Wrong or misspelled username on the form. If the username you submitted has a typo, or you had not created the account yet, submit the registration form again with the correct username. Your latest response replaces the earlier one, and your access is fixed in the next update.
  • Not released yet. Repositories are created batch by batch. If your lab batch has not been released, the link will 404 until it is.
  • Still stuck? Contact your lab TA with your roll number and your GitHub username.

How to do the assignment

Red boxes show where to click. There are two ways to submit — pick either one.

Option A — edit straight on GitHub (no download)

Simplest if you only need to change a few lines. Your edit is committed the moment you press the green button, so this submits your work by itself.

Option B — download, check on your machine, upload back

B2. Edit main.cpp in any editor, then open a terminal in that folder and run the check:

cd helloworld-B3-260000000-main
chmod +x check.sh
./check.sh

Unzipping removes the executable bit, so the chmod line is needed once. A pass looks like PASS: output contains roll number .... The check reads your roll number from the folder name, so do not rename the folder.

Editing on your own machine does not submit anything. Your submission is whatever is stored in your GitHub repository. After committing, open main.cpp on GitHub and confirm your own code is there. The last commit on main at the deadline is what gets graded.
